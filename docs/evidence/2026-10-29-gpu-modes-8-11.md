# Adreno 650：模式 8–11 的真机读数（2026-10-29）

本文件是 `porting.toml` 中 gpu area 的 evidence 指向。镜像 `mun-b3`（模式 7）、`mun-g9`（模式 9，payload 覆盖）、
`mun-b8`（模式 10）、`mun-b9`（模式 11），串口日志由 `cat /dev/tty.usbmodem* | tee` 采集。

## 模式 7（mun-b3）：GMU 上下文与冷启动

```
GPUROW13 GMUCTX step 7 status 0 kit 0/0 routes 2 id2 5511 phase 5 wr 13 rb 1 en 1
GPUROW14 LOAD status 0 phase 8 blocks 16 version 20010008 init 00000100 hfi 00000001 ready 11 ao 00000000 cm3 00000001 reset 0 r
GPUROW15 HFI status 0 stage 8 acked c6 error 0 transport 0 sent 4 4 ms skipped 0/0/0 health 0
```

结论：`status 0`、`routes 2`、HFI `acked c6` —— GMU 冷启动完成。此前 `status e00002ca / routes 0` 的原因不是
"SMMU 拒绝 EL1 写"，而是 `ArmSmmu4K` 的旧判据要求未使用的 S2CR 恰好等于 FAULT；这颗 Adreno SMMU 的槽位读作
`0x000203ff`（FAULT 类型 + CBNDX 0xff）。换到 pipa 分支的 kit（`9fbc33a`，只检查类型）后通过。

## 模式 8：GX 上电

```
GPUROW17 GX on perf 7 vote 0 oob 2 gx 000000c0>00000000 gdscr f8222800 rbbm 00000001 gbif halt 0/3 rbbm halt 0/0
```

`vote 0`、GX 状态寄存器 `c0→0`、OOB 两次轮询完成。汇总行的 `gpu=skip` 是上电前读取的，不是失败。

## 模式 9：第一条 GPU 命令

```
GPUROW18 GPUCTX step 7 status 0 kit 0/0 routes 4 program 5/1/1 ttbr0 0 smr 00000000 s2cr 00000000 actlr 3 pool 768
GPUROW19 CP ok step 7 sqe 31628/0 ring 0 init 0 fence 0/1 write 0 marker a6500c0d | hwcg 0>8aa8aa82 sptp 0>0
GPUROW20 CPSTATE rbbm 00000001 rptr 1b wptr 1b hwfault 0 cpint 0 int0 00100000 cb0 fsr 00000400 far 000037df57c2d167
```

GPU 自己的 SMMU 上下文（bank 0 / ASID 2）建成；ring 上的 `CP_MEM_WRITE` 把 `0xa6500c0d` 写进 scratch 页并由 CPU
读回，`rptr=wptr=1b`、`hwfault 0`。`int0 00100000` 是 CP cache-flush 时间戳挂起位，模式 10 消费它。

## 模式 10：zap + GPU 中断

```
GPUROW21 ZAP ok step 7 init 0/0 mem 0/0 auth 0/0 resumes 0 ms 14/0/1 phdrs 3 reloc 1 span 1000 secure 0 meta 1125f1000
GPUROW22 IRQ attach 0 readback a002 router 0 count 1>2 nop fence 1 seen 00100000 status now 00000000 masked 0
```

`init/mem/auth` 全 0、`secure 0`：TrustZone 接受镜像，`mem_setup` 与 `auth_and_reset` 完成，`CP_SET_SECURE_MODE(0)`
的 fence 走完。GPU 中断（SPI 332）挂上，`CP_NOP` fence 让计数从 1 涨到 2。

**zap 来源**：镜像必须是本机的。K40 内核导出里的 `redwood_fw_a650.c` 与手机 `/vendor/firmware/a650_zap.mdt`
+ `a650_zap.b02`（8536 B）有 **787 字节不同**，`pas_init_image` 返回 `0xffcfffbb`（PIL "failed to validate
firmware metadata"，与 QFIL 日志里同一 SMC id `0x42000201` 的返回值一致）。换成 vendor 镜像后通过。程序头保留
签名时的偏移（hash 0x1000、段 0x3000）；元数据缓冲按 Linux `mdt_loader` 的 split-firmware 规则构造：ELF 头后
**直接**跟哈希段，中间不留填充。`a650_gmu.bin` 与 `a650_sqe.fw` 与本仓库原有数组逐字节相同，无需替换。

## 模式 11：发布与 user client

```
GPUROW23 PUBLISH ok submit 0 timer 0 publish 0 | uc 36/36 first 0 at 0 cpumap 0 | rounds 4 4
GPUROW25 LIVE irq4 last100000 seen100000 m0 | sub 2/2 t1 p0 | uc 2/2 | pool 0/0/768 fb0 sc12 | busy 0
```

提交对象、CP 计数器时钟、设备发布和两轮 user-client（打开、BO、IB、fence、关闭）全部通过。内核侧 A650 链路到此完整：
GMU 冷启动 → GMU/GPU 两套 SMMU 上下文 → CP ring 与 fence → zap 认证 → GPU 中断 → 设备发布 → user client。

## 尚未完成

模式 12（Metal）仍被编译关闭。`IOAcceleratorFamily2` 不在预链接内核里，但这代 OS 的加速器基类是
`IOAcceleratorES`（`IOGPUFamily` 与 `IOAcceleratorES` 字符串都在内核里）。要启用需要针对本内核做一次
`IOAcceleratorES` 的运行时 ABI 审计（现有脚本 `audit-target-accelerator-base.py` 绑定的是 sheng 内核的观察地址），
再接 AdrenoMetal 插件与 Turnip/metal2vulkan addon。
